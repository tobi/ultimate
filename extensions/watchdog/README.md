Reports failed runs to their subagent owner or @ultimate.

Provider errors classified as temporary by Pi, and Claude Code relay responses that ended incomplete with status 200 or unknown, get one continuation after 60 seconds. A broken login (“not logged in”, a failed OAuth refresh, `invalid_grant`) is reported at once with a hint to log in again that names the provider (`diagnose` in `server.ts`). A used-up provider quota (`insufficient_quota`, “quota exceeded”, “usage limit reached”, or a gateway's “You've hit your daily premium model limit … resetting at … (2026-11-12 05:00 UTC)”) is never retried: the card's hint names the reset time when the error gives one with a zone, says every run fails until then, and leaves switching provider or model to the user. Later failures against the same reset are grouped: each recipient gets one card per reset, and the rest are only recorded in `watchdog.reported` (the root's `watchdog.receipts` keeps the reported resets until they pass). If someone has resumed the conversation and it is busy at that deadline, watchdog leaves it alone. `subagent stop` cancels that child's pending watchdog task and withdraws any queued retry input, using the stop handler's captured identities so replay leaves later work alone. A failed retry is never retried again. Persistent and non-temporary errors become a `watchdog.failure` card with the conversation, title, error, last tool step and any login hint; reporting a subagent's failure marks its parent's `failed` action for it `given-up`. @ultimate's own failure raises a notice instead. User Stops are ignored; reply-expecting Messages inputs already have a failure reply and are excluded. A `board.delivery` task that faults (the failure reply itself could not be sent) becomes a `watchdog.failure` card for the message's sender, or @ultimate when the user sent it, with step `message delivery`.

A root receipt and background task are created atomically for each failed generation; retry/report submissions use stable request IDs. On open, missed failures are scanned above the stored high-water mark, never advancing past unfinished work. Fresh installation marks existing tasks as historical and reports none of them.

Older transcripts may hold `watchdog.idle` notes from a retired idle-branches reminder; they still render. What each branch waits on now shows in the sidebar (`lib/waits.ts`).

Watchdog keeps the last 20 reported failures (`watchdog.reported` on the root, written with each report, including @ultimate's own) and serves them through `WatchdogApi.failures(since)`, newest first; the `status` extension reports them.
